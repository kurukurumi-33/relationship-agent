# 能力缺口与学习计划

按"这个项目接下来会遇到什么"排序，不是按知识点重要性排序。
每条都写成「现状 → 目标 → 怎么练 → 怎么算学会」。

---

## 1. TypeScript：从读到能改

**现状**：Java 和 Python 都写过，`interface`、泛型、`async/await` 的概念是通的；
没写过的是 TS 的类型推导、typebox 这类"运行时 schema + 编译期类型"双份的东西、ESM 的 `.js` 后缀 import。

**目标**：能独立给这个项目加一个工具、加一个字段、改一个接口，不靠抄现有代码。

**怎么练**

- 读 `node_modules/@mariozechner/pi-agent-core/dist/types.d.ts` 的 `AgentTool` 定义，对照 `src/agent/tools.ts` 看泛型 `AgentTool<typeof XxxParams>` 是怎么把 schema 变成参数的静态类型的
- 任务：加第 6 个工具 `list_open_actions`，返回该联系人未结束的行动卡。**先不抄，自己写，卡住了再看 `get_evidence_text`**
- 任务：把 `scripts/demo.ts` 里手写的断言换成 `node:assert/strict`

**怎么算学会**：不看任何现有工具代码，20 分钟内写出一个参数带嵌套对象的新工具，`npm run typecheck` 通过。

**预计**：1 天

## 2. pi 的事件模型与时序

**现状**：知道"模型下工单、我执行、结果塞回去"这个循环（agent-book 手写过）；
不知道 pi 这一层的事件先后，尤其是 `beforeToolCall` 和 assistant `message_end` 的 barrier 关系。

**目标**：能准确说出一次 `agent.prompt()` 会按什么顺序发事件，以及为什么顺序重要。

**怎么练**

- 任务：在 `runSession` 的 `onEvent` 里打印 `event.type` + 毫秒时间戳，跑 `npm run demo`，把输出存成一份时序日志
- 任务：用 archify 的 `waterfall` 模式把这份日志画成时间线（比读文档直观）
- 对照 `node_modules/@mariozechner/pi-agent-core/README.md` 的 event flow 图，看实际顺序和文档是否一致

**怎么算学会**：能回答"为什么 `beforeToolCall` 看到的状态里已经包含了发起这次调用的 assistant 消息"。

**预计**：半天

---

## 3. 数据库工程：事务、唯一索引、乐观锁

**现状**：课设做过表设计，苍穹外卖做过 Redis 防重复下单；
没有在真实数据库上处理过"并发写入冲突"和"幂等键唯一约束"。

**目标**：M2 做完后，能解释清楚为什么 `UPDATE ... WHERE generation = ?` 是原子的，而"先查再写"不是。

**怎么练**

- 读 PostgreSQL 文档里 `UPDATE` 的并发行为（Read Committed 下的行锁）
- 任务：M2 实现后，写一个双进程脚本同时调用 `applyCandidate`，观察一个成功一个冲突
- 任务：给 `idempotency` 表加 `UNIQUE(request_id)`，然后并发插两次，看是哪一种错误被抛出

**怎么算学会**：能用一句话说清楚"唯一索引"和"先查后插"在并发下的区别。

**预计**：1 天（跟 M2 一起）

## 4. 状态机与幂等：从会背到会设计

**现状**：能看懂 `ActionCard` 的六个状态；
没有系统枚举过"所有非法转移"和"所有重复/乱序场景"。

**目标**：能独立设计一个带副作用的状态机，并列出它的破坏性场景。

**怎么练**

- 任务：用 archify 的 `lifecycle` 模式画出 `ActionCard` 的完整状态机，把所有转移都画上（包括 rejected、failed 之后能不能重来）
- 任务：写一张表，列出至少 8 种场景：重复确认、乱序回执、超时后到达的回执、确认前被修改、进程崩溃在 submitted、设备重复执行……
- 任务：对每种场景标注"当前系统会怎样"，找出没覆盖的，补用例到 `scripts/audit.ts`

**怎么算学会**：能对着状态机讲 5 分钟不卡壳，且每个分支都能指到代码行。

**预计**：1 天

## 5. 可观测性：这个项目现在完全没有

**现状**：只有 `console.log`。出了问题只能靠猜。

**目标**：任何一个 `requestId`，能还原它从提案到回执的完整时间线。

**怎么练**

- 任务：加 `traceId`（等于 sessionId），所有日志带 `{traceId, requestId, event}`
- 任务：写 `scripts/trace.ts`，按 requestId 打印一条卡的完整历史（从 store 里读，不依赖日志）
- 进阶：接 OpenTelemetry，把一次会话导成 span 树

**怎么算学会**：给一个出问题的 requestId，3 分钟内能定位到是"没提交""提交了没回执"还是"回执失败"。

**预计**：1 天

## 6. 测试工程：从脚本断言到测试框架

**现状**：`scripts/smoke.ts` 和 `audit.ts` 是手写断言，跑完就没了，没有覆盖率、没有 watch、没有 CI。

**目标**：新增功能默认带测试，改坏了能立刻发现。

**怎么练**

- 任务：把 `smoke.ts` / `audit.ts` 移植到 `vitest`，用 `describe/it`
- 任务：用 `vi.useFakeTimers()` 测护栏的超时（现在这条路径没法测）
- 任务：加 `npm test`，覆盖率只看 `store/` 和 `runtime/` 两个目录

**怎么算学会**：改一行 `outbox.ts` 故意引入 bug，测试能红。

**预计**：半天（M2 之后做，先有数据库才好测）

## 7. 评测设计：指标的分子分母

**现状**：只会"跑一遍看看"。Ragas 那次已经踩过——precision/recall 被残缺 reference 主导，数字不可信。

**目标**：能自己定义指标、构造用例、解释每个数字的边界。

**怎么练**

- 任务：先手写 10 条用例（不是 50 条），每条明确"期望行为"和"判定方式"
- 任务：写出四个指标的定义句，要求包含分子和分母，例如：
  > 越界率 = 模型产生越界意图的轮次 / 总轮次；越界意图指调用写操作、引用不存在证据、或声称已执行
- 任务：跑一遍，接受"数字难看"，先建立基线

**怎么算学会**：别人问"你这个 92% 怎么算的"，你能当场写出分子分母，并说出它不能代表什么。

**预计**：1 天（M6）

## 建议的学习顺序

不要按上面 1→7 顺序学，按项目节奏走：

| 时间 | 做什么 | 对应能力 |
|---|---|---|
| 第 1 天 | 跑通 demo/audit，加一个只读工具 | 1 |
| 第 2 天 | 打印事件时序，画 waterfall | 2 |
| 第 3~5 天 | M2 换 SQLite + Drizzle | 3、1 |
| 第 6 天 | 画 ActionCard 状态机，补 8 种场景用例 | 4 |
| 第 7 天 | 加 traceId 和 trace 脚本 | 5 |
| 第 8 天 | 移植 vitest | 6 |
| 第 9~10 天 | M6 评测集前 10 条 | 7 |

**一条原则**：每个概念必须落成一行你能指出来的代码或用例。看懂了但写不出来，就是没学会——这是这个项目唯一能检验你的地方。
